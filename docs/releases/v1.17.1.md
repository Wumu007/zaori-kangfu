# 早日康复 v1.17.1 · 修掉 V1.17.0 我引入的一个回退

## 一、先说结论

V1.17.0 的**方向是对的**（闹钟直接拉界面，绕开速冻），但我自己复核代码时发现
**4 个问题，其中 1 个是那一版新引入的回退**。这版全部修掉，建议直接装 1.17.1，
不要停在 1.17.0。

## 二、最要紧的那个回退：改了时间/删了药，旧闹钟还会响

V1.17.0 把闹钟的「operation」从**广播**改成了**界面**，但取消闹钟的代码没跟着改 ——
它还在按广播那一条去取消。Android 里这两种是不同的东西，互相匹配不上，
所以**界面那条根本取消不掉**。

后果很具体：

| 你的操作 | 1.17.0 的表现 |
|---|---|
| 把早上 8:00 改成 9:00 | 明天 8:00 仍会突然弹出响铃页，说该吃药了 |
| 删掉一种药 | 那种药的旧提醒还在，最长残留 **7 天** |
| 把药停用 | 同上，每天照响 |

而且因为旧提醒已经不在新排程表里，App 内部没有任何地方能把它清掉 —— 只能等它自己过期。

**修法**：取消时把三种 PendingIntent 全部取消（广播那条、界面那条、锁屏图标那条），
并且把顺序改成「先按旧表取消 → 再写新表 → 再重排」。上一版是先写新表，
旧 id 就此失联，谁也找不回来。

## 三、响铃页会被叠两层，返回要按两次

V1.17.0 是「双路齐发」：主路拉界面，2 秒后广播再起响铃服务。但响铃服务起来后
**无条件又会 startActivity 一次** —— 于是第二个响铃页盖在第一个上面，按返回要按两次。
这正是 V1.15.0 花了一版修掉的老问题，这版又冒出来了。

**修法**：响铃服务在拉起界面前先判断「界面是不是已经在响同一条提醒」。
是就跳过，只在真正的兜底场景才拉。

## 四、界面已经在前台，还被要求再弹一次全屏通知

V1.16.0 只改了响铃服务那份通知的「全屏意图」开关，**广播兜底那份一直是写死的 true**。
结果主路已经把界面顶起来了，2 秒后广播又发一条带全屏意图的通知，
系统把同一个 Intent 再投一次 —— 又叠一层。

**修法**：跟响铃服务保持一致，界面在前台时不再要全屏意图。

## 五、顺手修掉一个老 bug：通知按钮的「哪一条」丢了

你以前点通知上的「已服药」，动作能传回来，但**定位不到是哪一种药**。
原因是取数据时先把存储清空了，再去读 payload —— 那时候已经没有了，永远是空串。

**修法**：先读 payload，再清空。

## 六、这版你要怎么验证

1. 装上 1.17.1，别再装回 1.17.0；
2. 设置 → 电池 → 后台耗电管理，给「早日康复」开**允许后台高耗电**（这一项仍然是前提）；
3. 点「测试提醒（10 秒）」，**按 Home 键，手机放桌上不要碰**；
4. 期望：到点时**界面自己弹出来并开始响铃**，锁屏也一样；返回只需按一次；
5. 再验证取消逻辑：把某个药的时间改掉，等旧时间点过去 —— 旧时间**不应该**再响。

如果第 4 步还是不弹界面、只听到铃声或者什么都不响，请导出日志。
这版在关键节点都留了原生日志（`界面已在响同一条提醒，跳过重复拉起` / `由闹钟直接拉起，立即响铃` /
`闹钟触发`），一眼能看出是哪一环没走通。
