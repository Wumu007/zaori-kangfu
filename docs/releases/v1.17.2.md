# 早日康复 v1.17.2 · 修「已处理后铃声停不下来」+ 测试提醒不再弹通知

## 一、你描述的现象，日志里能对上

> 点「已处理」后铃声不停止；只有再点一次通知栏里那条测试提醒才停；
> 锁屏点「已服药」回到界面，铃声照样不停。

导出日志里有一个决定性的细节：**整份日志里一条「停止响铃」都没有**。
也就是说，前台响铃服务从头到尾**没有被停过一次**。

同时，原生日志里出现了很多次「onNewIntent 带 payload，立即响铃」——
每点一次通知就多一次。所以你感觉的「点一下才响、再点才停」，
实际是**每点一次就新起一个声音**，越点越乱。

## 二、根因：一行 try 吞掉了释放动作（真凶）

原生停铃的代码原来是一行：

```kotlin
try { player?.stop(); player?.release() } catch (_: Exception) {}
```

`MediaPlayer` 在**还没准备好（Preparing）**的状态下调 `stop()` 会抛异常。
它和 `release()` 写在同一个 try 里 —— 异常一抛就跳到 catch，
**`release()` 从来没有执行过**。

于是三件事同时发生：

1. 播放器没释放，稍后准备完成，照样开始出声；
2. `player` 变量已经置空，**再没有任何句柄能停掉这个声音**（幽灵铃声）；
3. 每点一次通知就再造一个，声音叠着响，怎么点都停不干净。

你点「已处理」的那一刻，播放器多半正处在 Preparing 状态（铃声文件刚从
系统读取），所以这个 bug 几乎**每次都会命中**。

修法：

- `stop()` 与 `release()` 拆成两个独立 try，一个失败不影响另一个；
- 加一个「响铃代号」：每次停铃把代号 +1，准备完成的回调对不上就不出声、只释放；
- 停铃时先把各种监听器摘掉，杜绝回调再把它点燃；
- 每一步都写原生日志，下次能直接从日志看出停了几次。

## 三、另外三处遗漏（让问题看起来「停不下来」）

| # | 问题 | 修法 |
|---|---|---|
| 1 | 测试提醒的处理分支**只停了声音，没停前台服务**，通知永远挂在通知栏，用户一点就又响 | 补上停服务 |
| 2 | 进入响铃页时**无条件先响**，即使这条已经处理过 | 先判断是否已处理，已处理就不出声、直接退出 |
| 3 | 离开响铃页时，如果是「已处理」就**跳过收尾**（理由是「已经停过了」） | 改为无条件收尾，两步都幂等 |

还加了一道保险：处理过一条提醒后，原生会打一个标记（3 天后自动过期）。
之后同一条再被点开，**只展示、不出声**。「稍后提醒」不打这个标记，
那条本来就该再叫一次。

## 四、按你的要求：测试提醒不再弹通知

之前测试提醒会同时产生两条通知，其中「测试提醒：这是一条测试提醒…」
这一条纯属多余，还特别容易被反复点开（点一次就重新响一次）。

现在的行为：

- **界面成功弹出来并开始响铃** → 通知栏里**什么都不留**；
- **界面没弹出来**（锁屏被 ROM 拦了）→ 仍然走兜底发通知 + 起响铃服务，
  否则你会以为测试失败了；
- 真实用药提醒**不受影响**，照常有通知和三个按钮。

## 五、验证方法

1. 装 1.17.2（不要装回 1.17.0 / 1.17.1）；
2. 设置 → 电池 → 后台耗电管理，给「早日康复」开**允许后台高耗电**；
3. 点「测试提醒（10 秒）」，按 Home 键，手机放桌上；
4. 期望：到点**界面自己弹出来并响铃**，通知栏干净；
5. 在响铃页点「**已服药**」→ **铃声必须立刻停**，界面退出，通知栏也干净；
6. 再点开通知栏（如果还有残留）→ **不应该再响**；
7. 锁屏再测一次：锁屏上点「已服药」→ 铃声立刻停，跳回 App。

如果第 5 步铃声还不停，请立刻导出日志 —— 这次日志里会有
`ringStop 执行（gen=N）`、`ringStart 已发起（gen=N）`、`已标记处理` 这几类记录，
能直接看出是「没调用停」还是「停了又被拉起来」。
