# 早日康复 v1.17.3 · 找到数据丢失的真凶：每次安装包签名都不一样

## 一、先回答你的判断

> 这个 json 文件好像是随软件自动更新的，卸载就没了，重新安装重新写入。

**两点你都说对了：**

1. **会自动更新** —— 药品、记录、设置、密钥只要变一次，2 秒后就把整个保险箱重写一遍。
2. **卸载就没了** —— 它存在 `Android/media/com.medreminder.med_reminder/zaori-vault.json`。
   我原来以为这个目录「卸载不删」，**这是错的**。它和 `Android/data` 一样属于
   应用专属外部存储，卸载时系统会一并清除。

你上次重装的日志第一行就是证据：

```
16:58:16  启动时无需恢复 | 还没有备份      ← 文件已经不在了
16:58:18  保险箱已备份 | 221 字节          ← 这是新写的一份空备份
```

App 是「先发现没有备份」才写的，所以不是被它自己覆盖掉的，是**卸载那一刻就没的**。

## 二、但更严重的问题在后面：为什么每次都要卸载

我查了仓库的构建配置，发现**一个签名密钥都没配**。

后果是：每次云端构建都在全新机器上自动生成一个**随机**的 debug 签名。
于是每个版本的 APK 签名都不一样 → 手机安装时判定「签名冲突」→
**必须先卸载旧版**才能装新版 → 一卸载，所有数据（含保险箱）全没。

也就是说：

- 你以为的「重装」= 系统强制的「卸载 + 安装」；
- 每次更新都会走一遍，所以每次都要重填腾讯云密钥；
- 保险箱本身没坏，是**它所在的整个目录被连锅端了**。

这才是「数据全丢」的真正原因，比保险箱写在哪重要得多。

## 三、这次怎么修的

| 改动 | 作用 |
|---|---|
| 生成了一份**固定签名密钥**，放进仓库（`android/app/keystore.b64`），构建时用它签名 | 以后每个版本签名一致，**可以直接覆盖安装，不再丢数据** |
| `AndroidManifest` 加 `hasFragileUserData="true"` | 真到了要卸载那天，系统会问一句「是否保留应用数据」 |
| 构建日志里打印证书指纹 | 每次都能核对签名有没有变 |

修正了代码注释里「Android/media 卸载不删」这个错误说法，避免以后再踩。

## 四、⚠️ 这一次安装仍然要卸载一次

因为现在手机上那个版本用的是**旧的随机签名**，新的固定签名和它对不上，
系统仍然要求先卸载。**这是最后一次**，之后就稳定了。

**装之前请务必先导出备份**（如果现在还有数据要保）：

> 设置 → 导出备份 → 选个位置保存（可以发给自己微信/存到手机存储）

装完 1.17.3 后再用它「导入备份」恢复。

## 五、这次丢的数据还能不能找回来

老实说：**大概率不能**，因为文件是在卸载时被系统删除的，Android 没有回收站。
但有几条路值得你自己查一下，按可能性从高到低：

1. **你之前导出过的备份文件**（最可能）
   设置里的「导出备份」会生成一个 `早日康复-备份-*.json`，通常在你选的目录
   （下载 / 文档 / 微信文件传输助手）。找到后直接「导入备份」就能恢复。

2. **手机自带云备份**
   vivo：设置 → 账号与同步 → 云服务 → 数据备份，看有没有备份过这个应用。
   如果是「整机备份」且时间在你丢数据之前，可以还原（会覆盖当前数据）。

3. **换机助手 / 互传记录**
   如果你之前用 vivo 互传、手机搬家迁过数据，可能留了一份。

4. **文件管理器里的残留**（基本没戏，但看一眼不吃亏）
   打开文件管理，进 `Android/media/com.medreminder.med_reminder/`
   - 如果目录**不存在**或里面只有一个几十~几百字节的 `zaori-vault.json`
     （时间是你重装之后）→ 旧数据确实没了；
   - 如果有 `zaori-vault.json.tmp` 或体积几千字节以上的旧文件 → 把它拷出来，
     改名为 `zaori-vault.json` 放回原处，再打开 App 就能自动恢复。

5. 数据恢复软件（需连电脑、要 root 或用专业工具扫手机存储）——
   对普通用户不现实，而且被新数据覆盖后基本扫不出来。

## 六、以后别再丢的稳妥做法

1. 装完 1.17.3 之后，以后更新直接覆盖安装，不用卸载，数据不会丢；
2. 每月手动「导出备份」一次，存到微信收藏或电脑 —— 这是唯一真正可靠的；
3. 换手机/必须卸载时，先导出备份再动手。
