# 早日康复 v1.17.5 · 「守护图标在才响」的根因与自愈机制

## 一、你的观察说破了一切

> 通知栏里有「正在守护用药提醒」这个图标时，到点会提醒；
> 没有这个图标时，就不会提醒。

这句话比任何日志都直接。那个图标就是 `ReminderGuardService` 的前台服务通知 ——
**图标在 = 进程活着、有前台身份 = 系统不敢冻结它 = 闹钟到点能立刻被处理**。
图标不在 = 服务已经被系统清掉了 = 进程退回成普通后台 = 被冻结，
到点投递的广播只能排队，**你什么都感觉不到**。

所以不是「图标」本身有什么魔力，它是「进程有没有被系统善待」的可视化指示灯。

## 二、日志印证：服务确实死了，而且救不回来

V1.17.4 加的开机补排**是生效的**，日志里能看到：

```
10-31 12:41:57 [GuardAlarmReceiver] 系统事件 MY_PACKAGE_REPLACED → 补排第二通道 21 条
10-31 20:13:30 [GuardAlarmReceiver] 系统事件 BOOT_COMPLETED → 补排第二通道 20 条
```

问题在后面：从 12:43 到最后一次打开 App 的 20:13，**整整 7 个半小时，
原生日志里一条「存活 N 分钟，例行补排」都没有**。

那条日志由守护服务每 15 分钟写一次。7 个半小时本该有 30 条，一条都没有 ——
说明**服务早就不在了**，心跳、补排、拉起界面，全都跟着停摆。

为什么它回不来？`START_STICKY` 本来能让系统重建服务，但 **Android 12 以后
禁止应用从后台启动前台服务**，系统想重建也会被拒绝。于是服务一死就是永久死，
直到你下次手动打开 App。

**这就形成一个死循环**：服务死 → 没人补排 → 闹钟被系统清掉 → 到点不响 →
只有你主动打开 App 才恢复。

## 三、修复：给「自己」装一个闹钟

关键思路：能让**已经死掉的进程自己活过来**的，只有系统级的定时唤醒。
所以加一条「看门狗」：

**每 15 分钟醒一次，做三件事**

1. 先把下一次看门狗排上（链式自续，永不中断）；
2. 补排提醒闹钟（防止被 ROM 静默清掉）；
3. 守护服务不在跑 → 把它拉起来。

顺序不能反 —— 先续上链条，即使后面两步失败，15 分钟后还有机会。

这条看门狗由 `AlarmManager` 精确闹钟触发。Android 12+ 虽然禁止后台启动前台服务，
但**「精确闹钟触发的广播」属于豁免场景**（应用持有 `USE_EXACT_ALARM`），所以这一步合法。

**顺带修的第二处：图标为什么有时候根本不显示**

守护服务的通知渠道原来是 `IMPORTANCE_MIN`。MIN 级别的通知会被系统折叠进
「其他通知」里，图标直接看不见 —— 而恰恰你是靠这个图标判断后台是否正常的。

Android 8 以后渠道重要性**创建后不可修改**，所以换了一个新渠道 `med_guard_v2`，
重要性提到 `LOW`：仍然完全安静（无声、不震动、不亮灯），但**图标常驻可见**。

## 四、边界（必须说清楚）

- 看门狗本身也是闹钟，**手机重启后会被清掉** —— 这一层由 V1.17.4 的
  `BOOT_COMPLETED` 补排兜住（日志已证明有效）；
- 如果系统连开机广播都不给（自启动被禁），App 内任何机制都跑不起来，
  这一层只能靠系统权限。你截图里**自启动已开**，这块没问题；
- 建议顺手确认一项：**设置 → 电池 → 后台耗电管理 → 早日康复 → 允许后台高耗电**。
  这一项和「自启动」是两个不同开关，截图里没有覆盖到。

## 五、验证方法

装上 1.17.5，打开一次 App，然后按这个顺序测：

1. **看图标**：通知栏应该出现「早日康复 · 正在守护用药提醒」的常驻通知
   （以前是折叠状态，现在应该能直接看到）。
2. **杀掉服务试试**：设置 → 应用管理 → 早日康复 → 强行停止。
   然后**不要打开 App**，等 15 分钟再下拉通知栏 —— 图标应该自己回来了。
   这一步是这次修复的核心验证。
3. **跨夜测试**：正常用一晚，第二天早上导出日志，搜索
   `[GuardService] 存活` —— 如果每隔 15 分钟有一条，说明服务整夜都在，
   闹钟就不可能漏。
4. **到点验证**：按平时吃药时间，手机放桌上不碰，看是否自己弹界面并响铃。

如果第 2 步图标没回来，导出日志搜 `看门狗`：
- 有 `看门狗：补排 N 条，守护服务已尝试拉起` → 看门狗工作了，但系统拒绝拉起服务；
- 一条都没有 → 看门狗闹钟本身被清了，需要检查后台耗电那一项。
