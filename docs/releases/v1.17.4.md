# 早日康复 v1.17.4 · 修「偶尔不响」：重启 / 装新版之后闹钟会全丢

## 一、日志里最关键的三个事实

**① 10-31 08:32 之前，原生日志里一条「闹钟触发」都没有。**

整份原生日志从 10-27 18:01 直接跳到 10-31 08:32:07，
中间**没有任何 `[GuardAlarmReceiver] 闹钟触发`**。

**② 08:32:07 是「人打开 App」，不是闹钟拉起来的。**

```
08:32:07.366 [MainActivity] onCreate payload=null
```

如果是闹钟把界面拉起，这里一定带 payload。`payload=null` 说明是你自己点的图标。

**③ 打开后第一件事就是重排，而且确实排上了 21 条。**

```
08:32:07.880 第二通道已排 | 21 条（原生 alarm）
```

也就是说：**在你打开 App 之前，第二通道（负责弹界面+响铃的那条）是空的。**

于是到点只有 fln 那条通知躺在通知栏（它的 boot receiver 会自己重排），
没有铃声、没有界面 —— 你点开才响。这正是你描述的现象。

## 二、根因：系统清空闹钟后，第二通道没人补

Android 有两个时刻会**清空本应用通过 AlarmManager 排的全部闹钟**：

| 时刻 | 说明 |
|---|---|
| 手机重启 | 所有 alarm 归零 |
| 应用被更新（覆盖安装） | 包被替换，alarm 一起清掉 |

`flutter_local_notifications` 自带 `ScheduledNotificationBootReceiver`，
监听了 `BOOT_COMPLETED` 和 `MY_PACKAGE_REPLACED` —— 所以**通知批次会自动补回来**。

但我们的第二通道 `GuardAlarmReceiver` **只声明了接收器，没有监听这两个广播**。
结果就是：

- 通知：补回来了（你能看到通知）
- 闹钟：一片空白（没有铃声、没有界面）

这就解释了为什么是「**偶尔**不响」—— 只在「重启过」或「装过新版本」之后发生。
而且 V1.17.3 起改成覆盖安装了，**每次更新都会触发一次**，问题反而更容易出现。

## 三、这次怎么修

**① 给 `GuardAlarmReceiver` 加上开机与更新广播**

```xml
<intent-filter>
  <action android:name="android.intent.action.BOOT_COMPLETED" />
  <action android:name="android.intent.action.MY_PACKAGE_REPLACED" />
  <action android:name="android.intent.action.QUICKBOOT_POWERON" />
</intent-filter>
```

收到后立刻按持久化的排程表补排，并在日志里记「系统事件 xxx → 补排 N 条」。

**② 守护服务从「空转心跳」改成「真做事」**

原来 `ReminderGuardService` 每分钟只是 `postDelayed` 一下，什么都不检查。
现在每 5 分钟顺手把闹钟补排一遍 —— 用来兜住国产 ROM 在运行期间
**悄悄清掉第三方闹钟**（这种清空不发任何广播，只能靠定期补）。

补排是幂等的：同一条再排只会替换、不会重复响；已经过了点的那几条会被跳过，
也不会补弹旧提醒。

## 四、边界说明（这次修不到的部分）

如果手机在**长时间没打开 App** 之后把进程「深度冻结」甚至禁止自启动，
那么任何 App 内的机制都跑不起来 —— 这一层只能靠系统设置：

> 设置 → 应用管理 → 早日康复 → 权限/耗电
> - 自启动：**允许**
> - 后台耗电管理：**允许后台高耗电**
> - 电池优化：不限制

`hasFragileUserData`（v1.17.3 加的）和这个修复是两件不同的事，别混。

## 五、怎么验证这次修好了

1. 装上 1.17.4，打开一次 App（让它把闹钟排上）；
2. **重启手机**，不要打开 App；
3. 等到下一个吃药时间，观察是否自己弹界面 + 响铃；
4. 或者更快的验证：装完 1.17.4 后不要打开 App，直接等下一次提醒 —— 
   覆盖安装会触发 `MY_PACKAGE_REPLACED`，闹钟应该被自动补回。

如果还不响，导出日志看这一行：

- 有 `[GuardAlarmReceiver] 系统事件 ... → 补排 N 条` → 说明补排成功，问题在系统层拦截；
- 完全没有这一行 → 说明系统没把广播送到（vivo 的自启动限制），需要开自启动权限。
